## Task 0: リポジトリ作成と設計書・計画書の配置

- 目的: 設計書と計画書のみを含む初期リポジトリを作成し、GitHub に公開する。
- 内容: `README.md`、`docs/design.md`、`docs/plan.md`、`LICENSE`（MIT）、`.gitignore`（Rust / Node / Tauri）。
- デモ: GitHub 上で README・設計書・計画書が閲覧でき、mermaid 図が表示される。

## Task 1: プロジェクトの土台

- 目的: Tauri 2 + React/TS（Vite）+ Rust workspace（空の crate 群）でビルドとテストが通る状態にする。
- 内容: `crates/*` の雛形、clippy / rustfmt / ESLint / Vitest / `cargo test`、GitHub Actions（windows-latest）。依存はバージョンを固定する。
- テスト: 各 crate に最小限のテスト。
- デモ: アプリが起動し、Rust のコマンドでバージョンを画面に表示する。

## Task 2: 接続抽象化と SD カード読み取り、プロファイル、分類

- 目的: 指定フォルダ（SD カード）を読み、RAW + JPEG のペアにまとめて一覧表示する。
- 内容:
  - `DeviceSource` / `SourceCaps` の定義
  - `FsSource`（一覧・範囲読み込み・`local_path`）、テスト用の `FakeSource`
  - `CameraProfile` と TOML ローダ（スキーマバージョン・検証・ユーザーフォルダでの上書き）
  - `generic-dcf.toml` / `canon.toml`、Resolver
- テスト: ディレクトリダンプでの分類とペアリング、プロファイル判定、不正な TOML の検出。
- デモ: フォルダ選択で SD カードを指定すると、ペアごとの一覧が表示される。

## Task 3: モックデータでの UI 作成

- 目的: 実データなしで画面の操作感を確認できるようにする。
- 内容:
  - UI ⇔ Rust 間の DTO（`AssetView`、`DeviceView`、`RatingUpdate` など）を定義し、ts-rs / specta で TypeScript 型を生成する
  - `@tauri-apps/api/mocks` の `mockIPC` で約 50 件のモックデータ（撮影日時・評価付き、仮画像、読み込み遅延の再現）
  - 機器一覧、仮想スクロールのサムネイル一覧（TanStack Virtual。実カードは数千件想定のため仮想化は維持）、星の付与とフィルタ（キーボード操作・アクセシビリティ対応）、詳細パネル
  - `VITE_USE_MOCK` で切り替え
- テスト: Vitest + Testing Library で評価操作・フィルタ・キーボード操作。
- デモ: `npm run dev:mock` で、ブラウザ上で一覧表示・星の付与・絞り込みができる。

## Task 4: ExifTool によるメタデータ読み取り

- 目的: 撮影日時・機種・ボディシリアル・評価を一覧に表示する。
- 内容:
  - 冒頭でメタデータ関連の事前検証（design.md §10）
  - `-stay_open` の ExifTool の管理（起動・復旧・タイムアウト）
  - `read_range` で読んだ先頭バイトを stdin で渡す
  - プロファイルの `rating_tags` の順で評価を取得
  - Task 3 の UI に実データ（FS ソース）を接続
- テスト: 実機で撮ったサンプルファイル（fixture）で値を検証。
- デモ: 一覧に撮影日時と星が表示される。

## Task 5: カタログ（SQLite）と評価同期

- 目的: 評価の永続化とカメラ優先の同期。
- 内容: rusqlite + マイグレーション、識別キーでの upsert、`camera_rating` / `app_rating` / `app_base_rating` によるカメラ優先の上書き、アプリで評価を付けるコマンド。
- テスト: 同期判定の全パターンの単体テスト（core）、カタログの結合テスト。
- デモ: アプリで付けた星が再起動後も残る。カメラ側で評価を変えて読み直すと、カメラの値に更新される。

## Task 6: IO スケジューラとキャッシュ

- 目的: 優先度・epoch によるキャンセル・coalescing・3 段キャッシュを動かす。
- 内容: `IoScheduler`（機器ごとに単一ワーカー、P0〜P3、`set_viewport`）、メモリ LRU、ディスクキャッシュ（上限・SQLite 管理）、キャッシュキー。
- テスト: 遅延付きの `FakeSource` で、優先順・古い epoch の破棄・coalescing・キャッシュヒット時に機器へアクセスしないことを検証。
- デモ: 開発用画面で、処理待ち件数と処理済み件数をリアルタイムに表示する。

## Task 7: サムネイル一覧を実データへ置き換え

- 目的: Task 3 のモック UI を実データ（`thumb://`、スケジューラ）に置き換える。
- 内容: `thumb://` カスタムプロトコル（キャッシュ → スケジューラ）、サムネイル取得チェーン（埋め込み → Windows Shell）、`IntersectionObserver` で表示範囲を検知して `set_viewport`（約 100ms デバウンス）。
- テスト: 取得チェーンの単体テスト、UI テスト。
- デモ: 高速にスクロールしても表示中のものが優先され、再表示はキャッシュから即時。

## Task 8: 拡大プレビューと動画再生

- 目的: 写真の拡大表示と動画の画面内再生。
- 内容: RAW 埋め込みプレビュー JPEG の抽出、`<video>` での再生（FS は asset protocol）、失敗時に標準アプリで開く。冒頭で WebView2 の再生可否を検証。
- テスト: プレビュー抽出（fixture）、再生失敗時のフォールバックの UI テスト。
- デモ: 写真の拡大表示、MP4 の再生、CRM などは標準アプリで開く。

## Task 9: パステンプレート・ルールエンジン・計画プレビュー

- 目的: ルールを設定し、コピー計画を事前に確認できるようにする。
- 内容:
  - テンプレート記法: `{yyyy}{MM}{dd}{HH}{mm}{make}{model}{serial}{basename}{ext}{rating}`
  - ルール: 条件（星・種類）と動作（保存する種類・種類ごとの保存先）
  - 衝突ポリシー: 上書き（デフォルト、同一内容はスキップ）/ スキップ / 連番
  - `TransferPlan` の生成、ルール編集 UI、計画プレビュー（ツリー・件数・上書き件数・必要容量）
- テスト: テンプレートとルールの単体テスト（境界値、禁止文字、Windows のパス長）。
- デモ: 「星1 = JPG のみ、星2 = JPG + RAW、RAW は D ドライブの日付フォルダ」と設定すると計画ツリーが表示される。

## Task 10: コピー実行

- 目的: 計画どおりにコピーし、検証し、評価を書き込む。
- 内容: P2 でのチャンク読み込み（P0 割り込み可）、BLAKE3 の計算と書き込み後の検証、一時ファイル → atomic rename、XMP の書き込み（JPEG 埋め込み / RAW `.xmp` サイドカー）、取り込み履歴、進捗表示と中断。
- テスト: `FakeSource` → 一時フォルダで、衝突ポリシーの各種、検証の不一致検出、中断と再開。
- デモ: SD カードから実際に取り込み、取り込み済みのバッジが付く。

## Task 11: Windows MTP 接続

- 目的: USB 直結の Canon で SD カードと同じ機能を使えるようにする。
- 内容: 冒頭で WPD の部分読み込みを実機で検証。`windows` crate で WPD の一覧・範囲読み込み、`WPD_RESOURCE_THUMBNAIL`、動画はキャッシュへダウンロードしてから再生、ケイパビリティの申告。
- テスト: ダンプによる一覧・識別キーの検証、実機の手動テスト手順書。
- デモ: Canon をケーブルで接続し、一覧・プレビュー・評価・取り込みができる。

## Task 12: デバイス自動検知

- 目的: 接続すると自動で認識する。
- 内容: `DeviceWatcher`（WPD の機器通知、ボリュームの到着と DCIM の検出）、Resolver による自動プロファイル選択、取り外し時の処理列の停止と UI への反映。
- テスト: `FakeWatcher` による接続・切断イベントの状態遷移。
- デモ: SD カードの挿入、またはカメラの接続で自動的に表示される。

## Task 13: 設定画面と配布準備

- 目的: 配布できる状態にする。
- 内容: 設定画面（キャッシュ上限と削除、ユーザープロファイルフォルダ、衝突時のデフォルト）、ExifTool の同梱と第三者ライセンス表記画面、インストーラー（Tauri バンドラで MSI / NSIS）、コード署名手順の整理。
- テスト: インストール後のスモークテスト。
- デモ: インストーラーから入れたアプリで、接続から取り込みまで一通り動く。
